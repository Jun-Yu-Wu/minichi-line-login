# LINE 入口設計範例

更新日期：2026-10-24。共用規格見 [小日辰設計規範](../../design.md)。

本頁以使用者已確認的黑白「最後一步」為基準，記錄公開 LINE 綁定入口及結果頁的視覺規則。購前說明、社群暱稱、同意條件、OAuth 與管理員審核流程由現有產品規則決定。

## 0. 綁定入口

會員入口同時提供既有會員 LINE 登入與首次會員綁定。首次使用者會進入本頁；這個頁面保留社群暱稱、購前說明、同意後才前往 LINE Login 的既有順序。調整表單外觀不能改變同意門檻、社群暱稱比對或待審核分支。

- 標題直接說明「開始會員綁定」，社群暱稱使用可見 label。
- 使用小日辰白底、黑白灰文字、淡色分隔和黑色主操作，不加裝飾插圖、偽造步驟或不必要品牌色塊。
- 購前說明仍可完整捲動；使用者讀到底部並勾選同意後，才可前往 LINE 官方登入。

## 1. 最後一步的唯一工作

使用者完成可進入此結果頁的 LINE 綁定流程後，還需要把「已完成綁定」傳到官方 LINE。主操作開啟官方聊天室並預填訊息，使用者需在 LINE 中按下送出；頁面不宣稱訊息已送出。

閱讀順序固定為短任務標題、必要指示、預填文字、開啟聊天室。複製文字留作未自動帶入時的備援。

## 2. 桌面與手機線框

```text
桌面：內容靠左對齊，最大寬度 440px，周圍保留空間

               [SVG 驚嘆號] 最後一步

               開啟官方 LINE 聊天室，
               送出已填入的文字。

               ┌───────────────────────────────┐
               │ 已完成綁定          複製文字   │
               └───────────────────────────────┘

               [打開官方 LINE 聊天室          →]
```

```text
手機：左右 16px，可自然向下捲動

[SVG 驚嘆號] 最後一步

開啟官方 LINE 聊天室，
送出已填入的文字。

[已完成綁定                  複製文字]

[打開官方 LINE 聊天室               →]
```

標題使用黑白 Lucide `CircleAlert` 或既有相同語意 SVG，不使用 emoji 或裝置內建的彩色字符。一般內文與主要操作 16px，內容表面 `#F6F6F6`，主入口 `#202020`。

複製按鈕放在文字旁，視覺層級低於聊天室入口，觸控區至少 44px。窄螢幕或文字放大時，文字與複製操作可以換行排列，不縮小到難讀。

不加入登入完成摘要、成功慶祝、帳號介紹、FAQ、重複提醒、步驟紀錄或額外導航。

## 3. 操作與真實回饋

| 操作 | 預期行為 |
| --- | --- |
| 複製文字 | 僅複製精確字串 `已完成綁定`，成功後在原按鈕顯示「已複製」 |
| 複製失敗 | 保持文字可選取，於操作附近提示「請選取文字複製」 |
| 打開官方 LINE 聊天室 | 使用 LINE `oaMessage` scheme 開啟聊天室並預填「已完成綁定」：`https://line.me/R/oaMessage/%40903jhmgb/?%E5%B7%B2%E5%AE%8C%E6%88%90%E7%B6%81%E5%AE%9A` |
| 回到網頁 | 頁面仍提供同樣的複製與開啟入口，不推斷訊息是否已傳送 |

主入口保持可直接使用，不強制先按複製。使用者可能已是好友，不把操作命名為「加入好友」。

LINE 官方文件說明 `oaMessage` 可以開啟官方帳號聊天室並把文字放入輸入欄；其 URL scheme 支援 iOS 與 Android，不支援 LINE PC。頁面保留複製備援；網站不保證使用者已傳送訊息。參考：[LINE URL scheme](https://developers.line.biz/en/docs/messaging-api/using-line-url-scheme/)。

## 4. 其他結果狀態

「最後一步」只適用於已確認可繼續傳訊息的對應結果。待審核、名稱衝突、取消登入、登入失敗與一般錯誤各自使用真實標題及必要的下一步。

| 狀態類型 | 設計要求 |
| --- | --- |
| 同一 LINE 身分再次登入 | 標題「您已經綁定過嘍～」；提供「開啟官方 LINE」與「開啟小日辰會員中心」兩個入口。LINE 連結開啟官方帳號個人頁，不預填首次綁定訊息。 |
| 待審核／身分衝突 | 顯示實際等待狀態；不套用已綁定文案 |
| 使用者取消 | 顯示可重新開始的入口，不宣稱錯誤已修復 |
| 登入或驗證失敗 | 提供依現有流程可用的重試或返回；不暴露技術細節 |
| 需要購買規則或同意 | 保留必要內容與同意行為，不套用結果頁的刪字方式 |

已綁定重入頁沿用結果頁的白底、黑白灰卡片與清楚的主次操作；官方 LINE 為實心主要按鈕，會員中心為描邊次要按鈕。會員中心網址為 `https://minichi-customer-system.vercel.app/`。

官方 LINE 按鈕使用 `https://line.me/R/ti/p/%40903jhmgb`。LINE 官方說明此 URL 會開啟官方帳號個人頁；已是好友時會開啟一對一聊天室，因此重入時不再預填首次綁定訊息。參考：[LINE URL scheme](https://developers.line.biz/en/docs/messaging-api/using-line-url-scheme/)。

狀態分支、允許的重試與是否可進入該頁，沿用現有登入與綁定規則。文件不新增狀態碼或更動認證邏輯。

## 5. 情境驗收

- 在 320／390／768／1024／1440px，五秒內能找到待複製文字與聊天室主入口。
- 同一 LINE 身分重入時，顯示「您已經綁定過嘍～」及官方 LINE／會員中心兩個入口，不出現首次綁定的預填訊息區。
- 複製結果精確等於 `已完成綁定`，沒有引號、空白、換行或其他文案。
- 複製遭拒時仍可選取文字；輔助工具能讀取成功與失敗回饋。
- iOS／Android 主入口使用上表 `oaMessage` 網址，聊天室輸入欄顯示精確字串「已完成綁定」；LINE PC 不支援該 scheme 時可用複製備援。
- 200% 字體放大與矮視窗不裁掉標題或主操作。
- 以真實狀態分支核對待審核與失敗頁，不把所有結果呈現為已綁定。
- 網頁不因使用者點過連結就改成「訊息已送出」或「全部完成」。

以上為登入與綁定入口及結果頁的視覺驗收清單；正式 LINE OAuth、外部 LINE App 切換與實機訊息帶入仍須在隔離環境驗收。
